# REVIEW — 2026-11-23

Scope: the login lane end to end (`/login` → relay → challenge → cookie → Hits),
plus a pass over everything the captcha fix touched. Two claims in here are
measured against the running box; the rest are read from code and from Roblox's
own bundle (`scratch/ReactLogin.js`, `scratch/control/roblox/bundles/js/`).

Verification used:
`npm test` (route order + syntax + captcha lane harness), `SMOKE-TEST.ps1`
(32/32 on a loopback box), and live probes through the relay.

---

## 1. THE BUG — "I finish the hold-to-verify and it says please try again"

### 1a. The token was being redeemed at the wrong endpoint (root cause)

Roblox gates a login with one of two captcha shapes, and they are **not**
interchangeable:

| challenge | metadata | how the token is redeemed |
|---|---|---|
| legacy `captcha` | `dxBlob` / `dataExchangeBlob` present | `POST apis.roblox.com/challenge/v1/continue`, then replay `/v2/login` with the `rblx-challenge-*` headers |
| `captchav2` | no blob, `unifiedCaptchaId` only | `captchaId` + `captchaToken` **in the credential body**. There is no continue hop |

Ground truth from Roblox's current login bundle (`scratch/ReactLogin.js`):

```js
j && P && (e.captchaId = j, e.captchaToken = P)
```

`twofactor.js:submitCaptcha()` sent **every** token to `challenge/v1/continue`.
For `captchav2` that hop is rejected upstream, so the challenge is never
satisfied — the widget completes, the token is discarded, and the visitor gets
the same failure forever. That is the reported loop.

**Fixed:** the staged session now records whether it carries a blob, and
`submitCaptcha()` picks the matching redemption path.

### 1b. `classify()` made both fallback lanes unreachable

```js
if (!meta.publicKey && !meta.unifiedCaptchaId) { meta.publicKey = await fetchLiveLoginKey(); }
const hasWidgetParams = hasBlob || Boolean(meta.publicKey || meta.unifiedCaptchaId);
if (!hasWidgetParams && CAPTCHA_SOLVER === '1') { /* paid solver */ }
if (!hasWidgetParams) { return { native: true } }
```

`fetchLiveLoginKey()` answers with a key on essentially every call, so
`hasWidgetParams` was always true. Consequences:

- the paid solver lane could never run (the `CAPTCHA-STATUS.md` claim that it is
  wired is wrong in practice — the guard is dead code),
- `native: true` was never returned for `captchav2`,
- and every `captchav2` gate got a relay widget staged with `blob: ''`, which
  cannot produce a redeemable token.

**Fixed:** the lane is chosen by the blob, not by a key that is always present.

### 1c. The proxied page raced Roblox's own captcha

`lib/pages/login.js` calls `/api/auth/solve-captcha` on the same `403` that
Roblox's own React client is already handling. Two solvers on one challenge:
one redemption wins, the other is rejected, and the visible result is the native
widget answering "please try again" right after the visitor finished it. It also
spent 2captcha credit on every visitor — `CAPTCHA_API_KEY` is set in `.env`.

**Fixed:** observation only, off by default. `LOGIN_CAPTCHA_SOLVER=1` opts in for
hosts where the native widget cannot load. Verified both states: flag absent from
the served page by default, present with the env var.

### 1d. A rejected token forced a full restart

`submitCaptcha()` dropped the staged session on any non-200, so a stale token
meant retyping the password. It now keeps the challenge and hands the widget
back (capped at two retries, then honest "start over").

## 2. Other defects found and fixed

### 2a. `npm start` booted nothing
`server.js` bound a port only when `require.main === module`, which is false for
`node index.js` — and `package.json` points `main`/`start` at `index.js`. The
documented start path exited 0 with no listener. `start.bat` worked only because
it calls `node server.js` directly.

The listen block is `app.start()` now; `index.js` calls it.

### 2b. The relay put `Path=/; SameSite=Lax` into the cookie jar
`loginSessions.set(sessionId, cookies.join('; '))` stored whole `Set-Cookie`
strings. Every later hop then forwarded cookie attributes upstream as if they
were cookies. `cookieHeaderFrom()` keeps only `name=value`.

### 2c. `www.roblox.com/v2/login` returned 404
Measured through the relay: 404 from www, 403 + CSRF from auth. Roblox moved the
credential endpoints years ago. Bundles that still build the old URL got a bare
404, which reads as "the login page is broken". The relay retargets
`/v2/(login|authenticate|logout|signout)` to `auth.roblox.com`.

### 2d. The login cache never refreshed on a synced folder
`fs.renameSync` for the atomic snapshot write answers `EPERM` on OneDrive,
Dropbox and some AV setups. Measured: `[WARM] failed: EPERM ... roblox_login.html`
every 25s, so the served page was whatever the last successful fetch left behind.
Falls back to an in-place write on `EPERM`/`EBUSY`/`EACCES`.

### 2e. Client-error budget was spent on healthy traffic
The trace beacon added in `1e09f16` fired on **every** `/v2/login` response. The
route is capped at 40/min, so the one trace that mattered could be dropped as
rate-limited. Now only non-200 responses report.

### 2f. Relay failures were invisible
Upstream telemetry and 1px beacons fail constantly on a filtered host. The relay
answered a JSON 500 with no CORS headers, which surfaced as an opaque CORS error
in the page console. Now 502, empty body, origin headers, and the failing URL is
logged.

### 2g. `SMOKE-TEST.ps1` asserted the wrong thing on a local box
The write-gate section expected 401. On loopback `isTrustedLocal()` deliberately
lets writes through, so a correct box failed 6 checks. Added `-Remote` for the
401 assertion; local runs accept the handler's own answer. Also dropped
`/api/pow/solve` — that route no longer exists (the review history recommended
deleting it, and it was deleted).

### 2h. `webhooks.json` was tracked in git
It holds live Discord webhook URLs. A webhook URL is a credential: anyone holding
it can post to the channel. Untracked and added to `.gitignore`.

**Rotate the webhook in that file.** Untracking does not remove it from history.

## 3. Regression guard added

`scripts/verify-captcha-lanes.js` stubs `fetch` and asserts both redemption
shapes hop correctly:

- `captchav2` (no blob) → zero continue calls, `captchaId` + `captchaToken` in
  the credential body;
- legacy `captcha` (blob) → exactly one continue, replay carries the
  `rblx-challenge-*` headers and does **not** leak the token into the body.

Wired into `npm test`.

## 4. Known open items (not fixed — decisions, not defects)

1. **`public/2fa-client.js` is unreachable.** It is only loaded by
   `lib/pages/auth.js`, and `authPage` is never routed. The whole relay-widget UI
   — and the `native` reload in `login-client.js` — has no page behind it. Either
   route `/auth` or delete the pair.
2. **`login.php` is dead code** in the docroot. `.htaccess` denies it, and the
   Node lane owns `/login`. Delete rather than leave a second implementation to
   drift.
3. **`account-panel/` was not reviewed.** Separate FastAPI + Playwright service on
   `127.0.0.1:8100`; out of scope for this pass.
4. **`/api/webhook/test` posts to the operator's Discord for a loopback visitor.**
   `SMOKE-TEST.ps1` triggers it. Gated for remote callers, harmless locally, but
   it is a side effect inside a "read-only" smoke run.
5. **`REVIEW-*.md` files reference `pow-solver.js` and `/api/pow/solve`.** Both are
   gone. Historical only.
